> 환경: Claude Desktop App (Chat / Codex / Claude Code 사이드바)
> 진행: 3시간 실습 풀, AI 뉴스·복습은 대기시간 쿠션
> 날짜: 미정 (3회차=2026-05-19, 이월분부터 이어서 진행)
> 권한 전제: 엔터프라이즈 요금제라 **커넥터 authorize가 관리자 승인에 막힘** → 이번 회차는 처음부터 **MCP 수동 설정을 표준 경로**로 안내

## 이 회차의 위치 (3회차에서 이어짐)

3회차에서 실제로 완료한 것: Supabase 연결(커넥터 대신 MCP 우회) · 데이터 적재 · Git 커밋 · GitHub push.
**통째로 이월된 것: Vercel 배포 + Supabase 로그인.** 강사가 "다음 시간에 못한 작업부터 이어서"라고 명시.
Git/GitHub도 "다음 시간에 더 자세히"라고 예고 → 4회차 앞단에서 복습 심화.

그 위에 이번 회차 신규: **외부 API(Google Workspace / GCP)를 프로젝트에 붙이기 → 앱에 AI 넣기(Gemini API) → 제한사항(rate limit).**

> CLI(gog·gws·clasp) + Claude Code 자동화는 **5회차로 이월** (분량·난이도 조정).

## 페이지 4. Git/GitHub 복습 심화

> 🎤 **강사 멘트**: "지난 시간에 Git 설치하고 커밋, 깃허브 push까지 빠르게 지나갔잖아요. 오늘 그 의미를 한 번만 제대로 정리하고 갈게요. 이게 다음 배포의 입력이 되거든요."

> 💡 **Git = 코드 버전 관리**. 구글 드라이브의 "버전 기록"과 같은 원리.

### ▼ 1. 핵심 개념 3개만 (복습)

| 용어 | 비유 |
|---|---|
| **저장소** (Repository) | 프로젝트 폴더의 "버전 관리 모드" |
| **커밋** (Commit) | "여기까지 안전하다" 체크포인트 |
| **푸시** (Push) | 내 컴퓨터 → GitHub(클라우드)로 올리기 |

### ▼ 2. 왜 GitHub에 올리나 (한 번 더)

1. 내 컴퓨터가 망가져도 코드가 살아 있음
2. **Vercel 배포의 입력 데이터**로 쓰임 (바로 다음 단계)
3. git push 한 번 = Vercel 자동 재배포

### ▼ 3. 되돌리기의 한계 (3회차 보충)

- Claude Desktop의 `/rewind`(Esc+Esc), `/resume`은 **에러가 잦고 한계가 있음** → 그래서 Git을 쓴다.

### ▼ 4. 알아서 커밋되게 하기

```
/init
```
→ 생성된 `CLAUDE.md` 맨 아래에 추가:
```
파일을 수정할 때마다 깃에 커밋해줘.
```

> 💡 이러면 작업할 때마다 체크포인트가 자동으로 쌓여서, 언제든 안전하게 되돌아갈 수 있습니다.

### ▼ 5. 확인

- [ ] github.com → spigen-dashboard 저장소 보임
- [ ] 저장소에 `.env` / `.env.local` **없음** (있으면 즉시 삭제 요청)

## 페이지 5. Vercel 배포 (이월)

> 🎤 **강사 멘트**: "이제 진짜 인터넷에 올립니다. 지금까지는 본인 컴퓨터에서만 보였잖아요. 이거 끝나면 핸드폰으로 열어보세요. 어디서나 들어가집니다."

> 💡 **로컬호스트** = 내 컴퓨터만 / **Vercel 배포 URL** = 인터넷 어디서나

### ▼ 1. Vercel이 하는 일

- 내 GitHub 저장소를 받아서 자동 빌드·배포
- 매 push마다 자동 재배포
- 무료 도메인(`내프로젝트.vercel.app`) 제공
- Next.js를 만든 회사라 Next.js 배포가 특히 간단

### ▼ 2. 배포 절차 (웹 UI)

1. **vercel.com 로그인** (GitHub 계정으로 → 저장소 자동 연동)
2. **Add New → Project**
3. `spigen-dashboard` 저장소 옆 **Import**
4. **Environment Variables** 섹션 펼치기 → 로컬 `.env` 내용 그대로 복사·붙여넣기
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
5. **Deploy** → 1~2분 대기

### ▼ 3. 확인

- [ ] 배포 완료 화면의 URL을 **핸드폰 브라우저로 접속** → 차트 보임
- [ ] Supabase Table Editor에 데이터 있음

> ⚠️ 환경 변수를 빠뜨리면 배포는 되지만 **데이터가 빈 화면**으로 뜸. → Vercel 대시보드 → Settings → Environment Variables 추가 → Deployments에서 **Redeploy**.

## 페이지 6. Supabase 로그인 붙이기 (이월)

> 🎤 **강사 멘트**: "지금 이 상태면 링크 아는 사람 누구나 들어와요. 슈피겐 직원만 들어오게 막을 겁니다. 로그인 안 하면 화면 자체를 못 보게."

> 💡 **외부인 차단**: 슈피겐 임직원만 대시보드 접근 가능하게

### ▼ 1. Supabase Auth — Google 로그인 켜기

1. supabase.com → spigen-dashboard 프로젝트 → **Authentication → Providers**
2. **Google** Provider 켜기 → Google Cloud 콘솔에서 OAuth 클라이언트(웹 애플리케이션) 생성 후 Client ID/Secret 입력
   - 승인된 리디렉션 URI에 Supabase가 표시해주는 콜백 URL(`https://<프로젝트>.supabase.co/auth/v1/callback`) 추가
3. (선택) Email Provider도 켜두면 구글 계정 없는 사람 대비 가능

### ▼ 2. 실습 — Google 로그인 페이지 추가

```
Supabase MCP와 Context7 MCP를 활용해서 이 프로젝트에 다음을 추가해줘.

1. /login 페이지에 "Google로 로그인" 버튼 (Supabase signInWithOAuth, provider: google)
2. 대시보드 우측 상단에 로그아웃 버튼
3. 로그인 안 한 사용자는 대시보드를 볼 수 없고 자동으로 /login으로 리디렉션
4. Context7로 Supabase Google OAuth 모범 사례(Next.js App Router 기준)를 참고하면서 진행해줘
```

> 💡 **여기가 페이지 7과 연결되는 지점**: 이 Google 로그인에 Gmail·Calendar·Drive **권한(scope)** 을 같이 요청하면, 로그인 한 번으로 받은 토큰(`provider_token`)으로 페이지 7의 Workspace API를 그대로 호출할 수 있다. → **로그인 = Workspace API 인증**이 한 번에 끝남. (지금은 기본 로그인만, scope 추가는 페이지 7에서)

### ▼ 3. 재배포 + 확인

```
방금 작업한 내용을 GitHub에 커밋하고 푸시해줘.
커밋 메시지: feat: 로그인 기능 추가
```

매 push마다 Vercel 자동 재배포 → 1~2분 뒤 **시크릿 창**에서 확인.

- [ ] 비로그인 시 /login으로 자동 이동
- [ ] 회원가입 → 로그인 → 대시보드 흐름
- [ ] 로그아웃 → /login 복귀

> 💡 응용: "회사 구글 계정(@spigen.com 도메인)만 로그인되게 해줘" — 외부인 차단. (정식 화이트리스트/RLS는 운영 단계 주제)

## 페이지 7. 외부 API 연동 — Google Workspace / GCP (신규 메인)

> 🎤 **강사 멘트**: "여기서부터가 오늘의 새로운 부분이에요. 지금 우리 데이터, 결국 다 구글 시트에서 오잖아요. 그러면 시트를 직접 대시보드에 연결하면 어떨까요? 누가 시트에 숫자만 바꿔도 대시보드가 따라 바뀌게. 메일·캘린더도 같은 방식으로 붙일 수 있어요."

> 💡 **오늘 붙일 것**: 내 대시보드 프로젝트가 **구글 시트를 읽어오게** 하기 (확장: Gmail로 리포트 발송, Calendar에 일정 등록)

### ▼ 1. "API를 붙인다"가 뭔가

> 💡 **API** = 프로그램끼리 데이터를 주고받는 약속된 창구. 구글 시트도, 메일도, 캘린더도 다 API를 열어두고 있어서, 우리 프로그램이 그 창구로 데이터를 요청할 수 있습니다.

- **커넥터/MCP 없다면** → 시트 데이터를 매번 CSV로 내려받아 직접 넣기 (3회차에 했던 그 고생)
- **API로 붙이면** → 시트가 원본, 대시보드는 항상 최신 시트를 읽음

### ▼ 2. gcloud로 API 켜기 + 인증 만들기 (프롬프트로)

> 💡 **gcloud가 뭔가** = 구글 클라우드(GCP)를 **명령으로 조작하는 도구**. 콘솔에서 마우스로 클릭하던 걸 명령 한 줄로 한다고 보면 됩니다. gcloud로 **조작할 수 있는 것**:
> - **프로젝트** 만들기·선택
> - **API 켜기** (Sheets·Drive·Gmail·Calendar 등 — "이 기능 쓸게요" 스위치)
> - **서비스 계정**(앱이 쓸 로봇 계정) 만들기 + **키 발급**
> - IAM(누가 뭘 할 수 있나) 권한 설정
>
> ↔ 반대로 gcloud로 **안 되는 것**: 시트에 사람/계정 공유(Drive 권한), OAuth 동의화면·클라이언트 생성(콘솔 GUI). 시트 데이터를 실제로 읽는 건 우리 앱 코드가 합니다.

> 💡 **왜 콘솔 클릭이 아니라 gcloud인가**: 우리 회사는 커넥터·타사 앱 authorize가 관리자에 막혀 있는데(3회차에 겪음), 그 잠금은 **gcloud 경로엔 안 닿습니다**(두 평면이 분리됨). 그래서 본인 Owner 프로젝트면 gcloud로 막힘없이 됩니다.

> ⚠️ 그리고 **명령어를 외울 필요 없습니다.** 학생은 Claude Code에 **자연어 프롬프트로 시키고**, Claude Code가 알아서 gcloud 명령을 실행합니다. 콘솔 메뉴를 헤매던 이번 회차 최대 난관을 프롬프트 한 덩어리로 대체합니다.

**사전 1회 — 로그인.** Claude Code에 이렇게 시키면 됩니다 (로그인 창만 사람이 직접 누름):
```
gcloud로 내 구글 계정에 로그인하고, 내가 Owner인 <내-프로젝트-ID> 프로젝트를
활성 프로젝트로 설정해줘. 프로젝트가 없으면 새로 만들어줘.
지금 어떤 계정·프로젝트가 활성인지도 알려줘.
```
> 로그인은 브라우저 인증 창이 떠서 **한 번만 사람이** 진행합니다(이 단계만). 나머지는 Claude Code가 처리.
> ⚠️ **반드시 "본인이 Owner인 프로젝트"여야 합니다.** 회사 계정이어도 본인 Owner 프로젝트면 API 켜기·SA 생성·키 발급이 다 됩니다(sw.an 계정으로 검증). 처음에 막히는 흔한 원인은 org 정책이 아니라 **권한 없는 남의 프로젝트를 대상으로 한 것** — 활성 프로젝트부터 확인하라고 위 프롬프트에 넣어뒀습니다.
> ⚠️ **단, org가 서비스 계정 키 발급을 잠근 경우**(`iam.disableServiceAccountKeyCreation`)만 회사 계정으로 키 발급이 막힙니다. 이때는 **개인 gmail 프로젝트로 우회**하거나 관리자에게 정책 예외 요청(맨 아래 "관리자 사전 허용 요청서").

**본론 — API 켜기 + 서비스 계정·키 발급** (콘솔 클릭 전체를 이 프롬프트 하나로 대체):
```
gcloud로 이 프로젝트에 Google Sheets API와 Drive API를 켜줘.
그리고 spigen-sheets-reader 라는 서비스 계정을 만들고 키(JSON)를 발급해서,
그 키의 client_email과 private_key를 .env.local에
GOOGLE_SERVICE_ACCOUNT_EMAIL / GOOGLE_PRIVATE_KEY 로 넣어줘.
키 JSON 파일은 .gitignore에 추가해서 절대 커밋되지 않게 해줘.
```

> 💡 **뒤에서 도는 실제 명령** (강사 참고용 — 학생은 위 자연어만):
> ```bash
> gcloud services enable sheets.googleapis.com drive.googleapis.com
> gcloud iam service-accounts create spigen-sheets-reader \
>   --display-name="Spigen Sheets Reader"
> gcloud iam service-accounts keys create ./sa-key.json \
>   --iam-account=spigen-sheets-reader@<PROJECT_ID>.iam.gserviceaccount.com
> ```
> 발급된 키 파일에서 `client_email`·`private_key`를 뽑아 `.env.local`에 넣고 `.gitignore` 처리까지 Claude Code가 이어서 합니다. (키 발급은 **절대 커밋 금지** — `.env`는 서버 전용 변수)

> 💡 **서비스 계정 = 로봇 직원**. 콘솔에서 만들든 gcloud로 만들든 결과는 같습니다. 이 로봇에게 시트를 "공유"해줘야 읽을 수 있어요(다음 단계).

> 📌 **인증 방식 정리**: **시트 읽기 = 서비스 계정**(서버가 자동으로 읽음, 위 gcloud 방식). **Gmail·Calendar·Drive(▼4) = 본인 계정 데이터라 OAuth** → 페이지 6 Supabase Google 로그인으로 처리. 시트만 서비스 계정이 더 단순.

### ▼ 3. 실습 — 시트를 대시보드에 연결

▼2에서 만든 서비스 계정 이메일(`spigen-sheets-reader@<PROJECT_ID>.iam.gserviceaccount.com`)을, 읽어올 시트의 **공유** 버튼에서 추가(보기 권한). → **이 한 단계만 시트 UI에서 손으로** 합니다(시트 공유는 gcloud 영역이 아님). 그다음 시트 ID를 `.env.local`의 `SHEET_ID`로 넣으면 됩니다.

```
Context7 MCP로 Google Sheets API를 Next.js에서 쓰는 모범 사례를 먼저 확인해줘.

그 다음, 서비스 계정 키(.env에 있음)를 사용해서
이 구글 시트(시트 ID: ____)의 '주문' 탭을 읽어와
대시보드의 데이터 소스로 연결해줘.

시트를 수정하면 새로고침 시 반영되게 해줘.
```

> ⚠️ 붙여넣기하면 시트 ID·탭 이름을 본인 것으로 꼭 바꾸기. 키 값 자체를 프롬프트에 직접 붙이지 말 것(이미 `.env`에 있음).

### ▼ 4. 확장 API 실습 (전원 실습, 전부 무료 — 카드/결제계정 불필요)

> 💡 전부 **같은 패턴**: API 사용 설정 → 로그인(OAuth) → 프롬프트로 연결. 하나씩 붙여봅니다.

> **API 켜기는 시트와 똑같이 Claude Code에 프롬프트로** (gcloud를 대신 실행해줌):
> ```
> gcloud로 이 프로젝트에 Gmail·Calendar·Drive·Docs API를 켜줘.
> ```
> 단 **OAuth 동의화면 + 클라이언트 ID 생성만은 콘솔 GUI**라 gcloud로 안 됩니다(여기만 클릭). 그 둘은 페이지 6 Supabase Google 로그인 설정에서 이미 만든 것을 재사용 → scope만 추가하면 끝.

> 📌 **왜 이 셋(Gmail·Calendar·Drive)만?** "내 계정 데이터를 OAuth로 붙인다"는 **한 가지 패턴**으로 통일돼 배우기 깔끔하고, 슈피겐 운영에 바로 쓴다(리포트 메일·점검 일정·문서화). 번역·감성분석·이미지 같은 ML이 필요하면 과금형 전용 API(카드 필요) 대신 **8번 Gemini**(무료 티어)로 처리. Maps·Cloud Translation/Vision/NL은 결제계정(카드) 전제라 강의 제외.

4-2. **Calendar — 점검 일정 자동 등록**
```

```

4-3. **Drive / Docs — 분석 결과 문서화**
```
'AI 인사이트'를 구글 문서로 저장하고 공유 링크를 만들어주는 기능을 추가해줘.
```

> ⚠️ **인증 — 페이지 6과 통합**: 셋 다 **내 계정 데이터라 Google OAuth** 필요. → **페이지 6 Supabase Google 로그인에서 Gmail·Calendar·Drive scope를 같이 요청**하면 그 토큰(`provider_token`)으로 여기 셋을 다 호출(로그인=인증 통합, 가장 단순). Sheets 읽기(▼3)만 서비스 계정. 전부 카드 불필요. ※ 민감 scope는 데모 때 '미확인 앱' 경고 → 테스트 사용자 등록으로 통과(운영은 Google 검증 필요).

## 페이지 9. API 제한사항 — 할당량 · rate limit · 인증

> 🎤 **강사 멘트**: "이거 신나서 막 호출하다 보면 갑자기 에러가 나요. '너무 많이 불렀다'고. 공짜로 무한정 쓰는 게 아니거든요. 한도가 어떻게 되는지 한 번만 짚고 갈게요."

> 💡 외부 API·AI API는 **공짜·무제한이 아님**. 한도를 알아야 안전하게 설계할 수 있습니다.

### ▼ 1. 꼭 아는 3가지

| 개념 | 뜻 | 슈피겐 맥락 |
|---|---|---|
| **Quota (할당량)** | 하루/분당 호출 가능 횟수 | Sheets: 분당 읽기 제한 / Gemini: 무료 티어 분당·일일 요청 한도 |
| **Rate limit** | 짧은 시간에 몰아치면 차단 | 시트 셀마다 호출, 행마다 Gemini 호출 → 즉시 한도 초과 |
| **인증 만료 / 비용** | 토큰 만료·유료 전환 | 서비스 계정 키는 만료 없음 / Gemini는 무료 한도 넘으면 과금 |

### ▼ 2. 한도를 피하는 설계 (실무 팁)

- 셀·행 하나씩 N번 부르지 말고 **한 번에 묶어서**(batch) 처리
- 결과를 캐싱해서 매 새로고침마다 호출하지 않기
- AI 요약은 "행마다"가 아니라 "버튼 누를 때 한 번" 또는 "하루 1회"

> ⚠️ 429 (Too Many Requests)가 보이면 호출이 너무 잦은 것. 주기를 늘리거나 batch로 묶기.

- **4회차**: 이월 마무리(배포·로그인·Git) + Sheets(입력) + Gemini(앱 내 AI) + **확장 1개(4-1 Gmail)**
- **5회차**: 확장 잔여(4-2 Calendar·4-3 Drive/Docs) + CLI 자동화
- 대안 A: 4회차에 4-1~4-3 다 하고, CLI는 5회차
- 대안 B: 배포·로그인을 과제/시연으로 압축하고 4회차에 API를 더 많이 (이월 완결도↓ 리스크)

> 읽어올 슈피겐 샘플 시트 1개 준비 + 서비스 계정 공유 세팅 (4회차분)

### 권한·환경 (엔터프라이즈 제약 + gcloud 경로)

- [ ] Supabase MCP / Context7 MCP가 `.mcp.json` 수동 설정으로 전원 동작하는지 (커넥터 authorize는 막힘 전제)
- [ ] **gcloud 풀 플로우 직접 테스트** (수강생 화면 캡처용) — 본인 Owner 프로젝트에서 아래가 다 통과하는지:
  - `gcloud auth login` → `gcloud config set project <ID>` → `gcloud services enable sheets.googleapis.com drive.googleapis.com`
  - `gcloud iam service-accounts create ...` → `gcloud iam service-accounts keys create ...`
  - org가 막아두면 `PERMISSION_DENIED` / `iam.disableServiceAccountKeyCreation` → 관리자 요청서 발송 or 개인 gmail 우회 결정
- [ ] **수강생 계정별 사전 점검** — 회사 계정 org 정책이 사람마다 다를 수 있으니, 가능하면 강의 전 수강생 1~2명 계정으로 키 발급까지 실제 확인
- [ ] **Gemini API 키** — Google AI Studio에서 발급 풀 플로우 테스트. 무료 티어 분당/일일 한도 확인 (수강생 동시 호출 시 한도 주의)
- [ ] **인증 경로 확정** — Gmail·Calendar·Drive는 **페이지 6 Supabase Google OAuth**로 통합(로그인 시 Workspace scope 같이 요청 → `provider_token` 재사용). Sheets 읽기만 서비스 계정. API 켜기는 gcloud, 동의화면+OAuth 클라이언트(Client ID/Secret·콜백 URL)만 콘솔 GUI → 풀 플로우 직접 테스트. 동의화면 **내부(Internal)**로 하면 '미확인 앱' 경고·테스트 사용자 등록 불필요. **과금형(Cloud Translation·NL·Vision·Maps)은 카드 전제라 제외**
- [ ] 관리자 사전 허용 3종(GCP 서비스 ON + Drive 외부 공유 허용 + SA 키 생성 정책 예외) 완료 여부 — 막히면 강사 계정 시연으로 전환

### 페이스·스필 우선순위 (3회차 지연 교훈)

- CLI 자동화(gog·gws·clasp)는 **이미 5회차로 확정 이월**
- 확장 3종은 전원 실습이므로 격하 불가 → **"전원 실습 시간 설계"의 4·5회차 분할**로 흡수. 4회차가 밀리면 4-2(Calendar)·4-3(Drive/Docs)도 5회차로 더 넘김
- 4회차 사수 라인: **이월 마무리 + Sheets + Gemini**. 여기까진 무조건 4회차 안에
- 긴 작업(배포 빌드, API 연동 생성) 대기 중 11번 AI 뉴스 / 9번 제한사항 설명을 끼워 공백 메우기
- 자동/권한우회 모드 부재로 수동 허용 반복 → 작업 프롬프트는 **계획 모드**로 한 번에 묶어 허용 횟수 줄이기

### 실패 시 fallback

- API 인증/키 발급에서 다수 막힘 → 강사 화면 공유로 함께 진행, 키는 강사 데모용으로
- 시트 연동 실패 → 3회차의 CSV 적재 방식으로 우회 (이미 동작하는 경로)
- Gemini 호출 실패(키·한도·CORS) → 서버 라우트에서 처리하는지 먼저 확인, 한도면 호출 1회로 축소해 개념만 시연

## (강사 전용) 슈피겐 관리자 사전 허용 요청서

> ⚠️ 학습자 비공개. gcloud 실습이 수강생 전원에게 막힘없이 되려면 강의 전 슈피겐 관리자에게 아래를 요청. 그대로 복사해 전달 가능.

### 필수 — Sheets 서비스 계정 경로 (강의 메인)

**① Workspace 관리 콘솔 (admin.google.com)**
- `앱 → 추가 Google 서비스 → Google Cloud Platform → 사용 설정(ON)` ⭐ 가장 자주 빠뜨림
  - OFF면 학생이 gcloud 로그인은 돼도 **프로젝트·API를 아예 못 만듦**. 학생 OU에만 켜도 됨.
- `앱 → Google Workspace → Drive 및 문서 → 공유 설정`: 서비스 계정 이메일로 시트 공유가 되게 **외부 공유 허용**(또는 신뢰할 수 있는 도메인에 `gserviceaccount.com` 추가) ⭐ 이게 막히면 키·SA 다 만들어도 **마지막 시트 공유에서 전원 막힘**
  - 슈피겐 도메인 입장에서 서비스 계정(`@xxx.iam.gserviceaccount.com`)은 외부 ID라, 외부 공유가 잠겨 있으면 공유 단계가 차단됨. 학생이 **개인 gmail로 시트를 만들면** 이 항목은 우회됨.

**② GCP 조직 정책 (console.cloud.google.com → IAM 및 관리자 → 조직 정책)**
- `iam.disableServiceAccountKeyCreation` → **미적용** ⭐ 서비스 계정 키 발급의 핵심 (org 전체 대신 실습 프로젝트/폴더에만 예외 override 권장)
- `iam.disableServiceAccountCreation` → 미적용
- 학생에게 `roles/resourcemanager.projectCreator` 부여 **또는** 관리자가 학생별 프로젝트를 미리 만들어 **Owner로 배정**(당일 더 안정적)

> Sheets/Gmail/Calendar API는 전부 무료 → **결제 계정(카드) 불필요**. gcloud 로그인 자체는 ①만 켜져 있으면 거의 별도 허용 불필요.

### 추가 — Gmail/Calendar/Drive OAuth 쓸 때만 (확장)

- `admin.google.com → 보안 → API 제어 → 타사 앱 액세스 관리 → 앱 구성`에서 학생이 만든 OAuth 클라이언트 **Client ID를 "신뢰함"** 처리
  - 대안: OAuth 동의화면을 **내부(Internal)**로 만들면 보통 이 단계도 불필요

### 그대로 보낼 요청 메시지 (예시)

```
슈피겐 바이브 코딩 강의(4회차) 실습 준비로 두 가지 사전 허용 요청드립니다.

1. admin.google.com → 앱 → 추가 Google 서비스 → Google Cloud Platform = ON
   (학생 OU 한정 가능)
2. admin.google.com → 앱 → Google Workspace → Drive 및 문서 → 공유 설정
   : 서비스 계정 이메일(@xxx.iam.gserviceaccount.com)로 시트 공유가 되도록 외부 공유 허용
   (또는 신뢰할 수 있는 도메인에 gserviceaccount.com 추가)
3. GCP 조직 정책에서 iam.disableServiceAccountKeyCreation = 미적용
   (실습용 프로젝트/폴더에만 예외 override 권장)

위 셋이면 학생들이 gcloud로 API 활성화·서비스 계정 키 발급, 시트 연결까지 직접 할 수 있습니다.
Sheets/Gmail/Calendar API는 전부 무료라 결제 계정은 불필요합니다.
Gmail·Calendar 확장까지 전원 실습하면 OAuth 클라이언트 Client ID 신뢰 처리도 부탁드립니다.
```

### 관리자가 현재 상태 확인할 read-only 점검 (선택)

```bash
# SA 키 생성 차단 정책이 적용돼 있는지 (booleanPolicy 비어있으면 미적용 = OK)
gcloud resource-manager org-policies describe iam.disableServiceAccountKeyCreation \
  --project=<실습-프로젝트-ID>
```
