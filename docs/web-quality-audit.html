먼저 — 이 앱의 성격이 우선순위를 결정합니다

이 프로젝트는 로그인 뒤 내부 광고 대시보드입니다. 검색엔진·AI 크롤러가 인증 벽 안쪽을 못 봅니다. 그래서:

• SEO/GEO — 최적화 대상이 아니라 노출 차단 대상. 진단 결과 대부분 N/A, 핵심은 "내부 데이터가 검색/AI에 새지 않게 막혔는가" 하나뿐.

• 성능 — 진짜 레버리지. RSC 미활용 + 번들 비대가 핵심.

• 보안 헤더 — 이미 상당히 잘 갖춰짐(CSP·X-Frame·Referrer·Permissions). 소수 보강만 필요.

Critical — 즉시 수정

Critical접근성 · WCAG 3.3.2
폼 label이 input과 프로그래밍적으로 연결되지 않음

src/app/login/page.tsx:117,131,169 .../mypage/ChangePasswordForm.tsx:44,55

문제 <label>이 시각적으로만 존재하고 htmlFor+id 연결이 없습니다. 스크린리더가 입력 필드의 이름(비밀번호·이메일 등)을 읽지 못합니다. accessibility 스킬이 "즉시 수정" 1순위로 지정한 항목입니다.

수정

<label htmlFor="new-password">새 비밀번호</label>
<input id="new-password" type="password" autoComplete="new-password" />

또는 input을 label로 감싸는 암시적 연결도 가능합니다. 로그인 폼은 보안 모범사례상 autoComplete 속성(current-password/email)도 함께 권장됩니다.

High — 출시 전 수정

High성능 · 번들
xlsx(SheetJS)가 클라이언트 번들에 통째로 포함

src/app/(dashboard)/upload/page.tsx:4 — import * as XLSX from "xlsx" (이 파일은 "use client")

실측 클라이언트 청크 0se0_xlsx_xlsx_mjs… = 1,080 KB (dev·비압축) 프로덕션 gzip 기준으로도 ~300–400KB로, upload 페이지 진입 시 그대로 다운로드됩니다.

수정 동적 import로 분리해 첫 진입 번들에서 제거. 더 나아가 파싱 자체를 서버(route handler/server action)로 옮기면 클라이언트에서 완전히 사라집니다.

// 클릭/업로드 시점에만 로드
const XLSX = await import("xlsx");
// papaparse도 동일 패턴 적용 가능
High성능 · LCP · 아키텍처
서버 컴포넌트(RSC) 미활용 — 전 페이지가 클라이언트 패칭

19개 페이지 중 15개 "use client" — 모든 대시보드 페이지가 useEffect → getSummary()/fetch 패턴.

문제 브라우저가 JS를 다 받아 실행한 뒤에야 데이터 요청이 시작됩니다. core-web-vitals 스킬의 LCP 악화 사례 #4 "Client-side rendering delays"에 정확히 해당. 페이지마다 빈 화면 → "로딩 중..." → 콘텐츠 순서.

수정 데이터 페칭을 서버 컴포넌트로 내리고, 상호작용이 필요한 차트/필터만 "use client"로 분리. vercel-composition-patterns 스킬의 "server-fetch, client-island" 패턴.

High보안 · SEO(역방향)
robots.txt / noindex 부재 — 내부 데이터 노출 위험

src/app/robots.ts (없음) sitemap.ts (없음)

문제 내부 매출·광고·재고 대시보드인데 크롤러 차단 정책이 명시돼 있지 않습니다. 인증 미들웨어가 1차 방어를 하지만, 로그인 페이지 메타데이터·URL 구조가 검색/AI에 노출될 수 있습니다.

수정 (일반 SEO와 반대 방향) 전역 noindex + AI 크롤러 차단:

// src/app/robots.ts
export default function robots() {
  return {
    rules: [{ userAgent: "*", disallow: "/" }],
    // GPTBot, ClaudeBot, PerplexityBot 등도 차단 의도
  };
}
// + layout metadata에 robots: { index: false, follow: false }

Medium — 스프린트 내 수정

Medium성능 · 스트리밍
loading.tsx / Suspense 미활용 — App Router 스트리밍 없음

src/app/(dashboard)/ 하위 loading.tsx·error.tsx 없음

각 페이지가 자체 "로딩 중..." 문자열로 처리. RSC 전환과 함께 loading.tsx + <Suspense>로 셸을 먼저 그리고 데이터를 스트리밍하면 체감 속도가 개선됩니다. error.tsx 에러 바운더리도 부재.

Medium보안 · 헤더
HSTS(Strict-Transport-Security) 헤더 누락

next.config.ts — securityHeaders 배열

X-Frame-Options·CSP 등은 잘 설정돼 있으나 HSTS가 빠졌습니다. best-practices·seo 스킬 모두 권장.

{ key: "Strict-Transport-Security",
  value: "max-age=31536000; includeSubDomains; preload" }
Medium보안 · CSP
CSP에 unsafe-inline/unsafe-eval, base-uri·form-action 부재

next.config.ts — script-src 'self' 'unsafe-inline' 'unsafe-eval'

주석대로 Next.js 호환을 위한 것이나, XSS 방어가 약화됩니다. nonce 기반 CSP로 강화 가능(복잡도 있음). 또한 best-practices 권장 항목인 base-uri 'self', form-action 'self'가 빠져 있어 이 둘은 부작용 없이 바로 추가 가능합니다.

Medium접근성
차트 텍스트 대안 없음 · 아이콘 버튼 일부 라벨 누락

recharts 4개 페이지 .../products/page.tsx:73 (✕ 버튼)

recharts 그래프는 스크린리더가 데이터를 읽지 못합니다 — 핵심 수치를 인접 테이블이나 aria-label/요약 텍스트로 보완 권장. 상품 상세 닫기 ✕ 버튼에 aria-label="닫기" 필요. (메인 메뉴 버튼은 이미 라벨 있음 — 양호)

Low — 여유 시 정리

Low성능 · 폰트
Geist 폰트 정의했으나 본문에서 미적용

layout.tsx (Geist 변수 주입) ↔ globals.css — body { font-family: Arial, Helvetica }

next/font로 Geist를 로드·변수화했지만 body가 Arial로 덮어써, Geist가 실제 본문에 적용되지 않습니다. 또 subsets: ["latin"]만 지정돼 lang="ko" 한글은 시스템 폰트로 렌더됩니다. 의도면 Geist 로드를 제거(불필요한 폰트 요청 절약), 사용하려면 body font-family를 var(--font-geist-sans)로 정리.

LowSEO
페이지별 metadata 부재 (내부툴이라 영향 미미)

layout.tsx에 전역 metadata만

일반 사이트면 페이지별 title·description이 필요하지만, 인증 뒤 대시보드라 SEO 가치는 사실상 없습니다. 브라우저 탭 구분 목적이면 각 페이지 export const metadata로 title만 다르게 주는 정도로 충분.

Low접근성 · 대비
저채도 텍스트(neutral-400/500) 색 대비 점검 필요

라벨·보조 텍스트에 text-neutral-400/500 사용. 배경 대비 4.5:1(WCAG AA) 미달 구간이 있을 수 있습니다 — 라이브 환경에서 axe/Lighthouse로 실측 권장. (정적 분석으로는 확정 불가)

GEO (생성형 엔진 최적화) — 적용 대상 없음

결론: N/A. seo-geo·ai-seo 스킬의 핵심 전제는 "공개된 텍스트 콘텐츠가 AI에 인용되게 한다"입니다. 이 앱은 인증 뒤 대시보드라 AI 크롤러가 접근할 콘텐츠가 없습니다. FAQPage 스키마·llms.txt·answer-first 구조 등 모든 GEO 기법이 적용 지점을 갖지 못합니다.

유일한 액션은 위 High 항목의 robots.txt로 AI 크롤러(GPTBot·ClaudeBot·PerplexityBot) 명시 차단 — 내부 데이터의 AI 학습·인용 방지. GEO와 정반대 방향입니다.

→ 외부 공개 마케팅/랜딩 페이지를 신설하면, 그때 이 두 스킬이 실제 가치를 갖습니다.

권장 실행 순서

  1. 폼 label 연결 + autoComplete 추가 — 접근성 Critical, ~15분
  2. robots.ts + noindex로 내부 데이터 노출 차단 — 보안, ~10분
  3. xlsx·papaparse 동적 import (또는 서버 파싱) — 번들 -300KB대, 효과 큼, ~30분
  4. HSTS + base-uri/form-action CSP 보강 — 보안, ~10분
  5. RSC 전환 — 데이터 페칭 서버화 + loading.tsx 스트리밍 — 구조적, 페이지별 점진 적용
  6. 차트 a11y · ✕ 버튼 라벨 · 폰트 정리 — 마무리
