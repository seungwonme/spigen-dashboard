# **2. 프롬프트 엔지니어링과 컨텍스트 엔지니어링**

바이브 코딩 → 결국 프롬프트로 AI에게 개발을 위임하는 것

## 프롬프트 엔지니어링

**AI가 최적의 결과물을 만들어낼 수 있도록, AI 프롬프트를 작성하는 방법**

**여러 기법들**

- **Role prompting:** 특정 인물이나 전문가의 역할을 부여하여 전문적인 답변을 얻기
- **Few-shot Prompting:** 예시를 보여주며 요청하기
- **Chain of Thought (CoT):** 사고 과정을 보여달라고 요청하기 → **추론 모델 (Reasoning Model)**
- **Meta prompting:** AI가 AI에게 줄 프롬프트를 만들게 하기

[AI를 위한 프롬프트 엔지니어링 가이드](https://cloud.google.com/discover/what-is-prompt-engineering?hl=ko)

## 컨텍스트 엔지니어링

**AI에게 적절한(최적화/설계하여) 정보(맥락)를 줘서 상황에 맞는 정확한 답변을 도출하도록 하는 접근 방법**

**`바이브 코딩` 단어의 창시자 OpenAI의 공동창업자 Andrej Karpathy가 리포스트한 글**

<aside>
💡

**Shopify CEO Tobi**

저는 '프롬프트 엔지니어링'이라는 용어보다 '컨텍스트 엔지니어링'이라는 용어를 훨씬 더 좋아합니다.

이는 핵심 역량을 더 잘 설명합니다. 즉, LLM이 과제를 그럴듯하게 해결할 수 있도록 모든 맥락을 제공하는 기술입니다.

- **Andrej Karpathy**
    
    ```json
    “프롬프트 엔지니어링”보다 “컨텍스트 엔지니어링”이라는 표현에 한 표를 던진다.
    
    사람들은 보통 프롬프트를 일상적으로 LLM에 입력하는 짧은 작업 지시문 정도로 이해한다. 하지만 실제로 산업 수준의 LLM 애플리케이션에서는, 컨텍스트 엔지니어링이란 다음 단계에서 필요한 정보를 컨텍스트 윈도우에 정확하게 채워 넣는 정교한 예술이자 과학이다.
    
    과학인 이유는, 이를 제대로 수행하려면 작업 설명과 해설, few-shot 예시, RAG, 관련 데이터(멀티모달일 수도 있음), 도구, 상태(state)와 히스토리, 압축(compacting) 등 다양한 요소가 필요하기 때문이다. 정보가 부족하거나 형태가 적절하지 않으면 LLM이 최적의 성능을 낼 수 있는 컨텍스트를 확보하지 못한다. 반대로 정보가 너무 많거나 관련성이 낮으면 비용은 증가하고 성능은 오히려 떨어질 수 있다. 이를 잘 수행하는 것은 결코 간단하지 않다.
    
    또한 이것이 예술인 이유는, LLM의 작동 방식과 인간의 직관을 결합해 적절한 판단을 내려야 하기 때문이다.
    
    컨텍스트 엔지니어링 자체를 넘어, 하나의 LLM 애플리케이션은 다음과 같은 요소들도 필요로 한다:
    	•	문제를 적절한 단위로 분해하여 제어 흐름(control flow)을 설계하기
    	•	컨텍스트 윈도우를 적절하게 구성하기
    	•	적절한 종류와 성능을 가진 LLM에 요청을 분배하기
    	•	생성과 검증을 포함한 UI/UX 흐름을 설계하기
    	•	그 외에도 다양한 요소들: 가드레일, 보안, 평가(evals), 병렬 처리, 프리패칭 등
    
    결국 컨텍스트 엔지니어링은, 개별 LLM 호출(그리고 그 이상의 요소들)을 하나의 완성된 LLM 애플리케이션으로 조율하는 복잡한 소프트웨어 레이어 중 일부에 불과하다.
    
    “ChatGPT wrapper”라는 표현은 이제 낡았고, 실제를 심각하게 왜곡하는 잘못된 표현이다.
    ```
    

### 어떻게 맥락(Context)을 효과적으로 전달할까?

**육하원칙, 5W1H**

- 핵심 정보를 빠짐없이 전달하기 위한 6가지 필수 요소인 **'누가(Who), 언제(When), 어디서(Where), 무엇을(What), 어떻게(How), 왜(Why)'**를 의미
- 의사소통의 정확성과 명확성을 높이는 데 활용

**What, How, Why가 중요 → How는 AI가 알아서 해주는 경우가 많음**

What, Why를 효과적으로 전달하는 프레임워크: [S.T.I.C.C](https://leadingstrategicinitiatives.com/2012/11/01/s-t-i-c-c-a-useful-communication-tool-for-critical-situations/)

- **상황 (Situation): 내 상황은 이래**
- **작업 (Task): 해야하는 일은 이거야**
- **의도 (Intent): 이 일을 해야하는 이유는 이 것 때문이야**
- **우려 (Concerns): 이 일을 할 때 이런 부분들이 우려스러워**
- **조정 (Calibrate): 이해가 안 되거나, 할 수 없거나, 너가 모르는 것이 있다면 내게 말해줘**
    
    → 질문하게 하기
    
- 예시
    
    ```json
    [Situation] 현재 우리 재무팀은 매일 환율, 원자재 가격, 경쟁사 공시 데이터를 수집해서 엑셀로 정리하고 있습니다.
    [Task] 이 과정을 자동화해서 대시보드 형태로 볼 수 있는 시스템을 만들고 싶습니다.
    [Intent] 반복 업무 시간을 줄이고, 의사결정에 필요한 데이터를 실시간으로 확인하기 위함입니다.
    
    [Concerns]
    - 데이터 출처가 안정적인지
    - 무료로 구현 가능한지
    - 유지보수가 복잡해지지 않는지
    
    [Calibration]
    - 내 의도를 정확히 파악하여 최적의 답변을 작성하기 위해 답변을 작성하기 전에 나에게 필요한 정보를 3가지 이상 단계적으로 모두 질문해줘
    - 현실적으로 어려운 부분이 있다면 대안도 제시해줘
    
    ```
    

**STICC 프롬프트 템플릿 (복사해서 쓰세요!)**

```markdown
[Situation] 내 상황은 이래
[Task] 해야하는 일은 이거야
[Intent] 이 일을 해야하는 이유는 이 것 떄문이야

[Concerns] 이 일을 할 때 이런 부분들이 우려스러워
[Calibration] 내 의도를 정확히 파악하여 최적의 답변을 작성하기 위해 답변을 작성하기 전에 나에게 필요한 정보를 3가지 이상 단계적으로 모두 질문해줘.
```
