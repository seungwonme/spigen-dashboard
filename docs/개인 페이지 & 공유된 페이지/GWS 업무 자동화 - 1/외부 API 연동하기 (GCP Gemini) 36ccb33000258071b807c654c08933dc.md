# 외부 API 연동하기 (Google Sheets + Gemini)

# 1. 외부 API란?

API는 프로그램끼리 데이터를 주고받는 약속된 창구입니다. 구글 시트도, 메일도, 캘린더도 API를 열어두고 있어서 우리 대시보드가 그 창구로 데이터를 요청할 수 있어요.

```
커넥터/MCP 없다면 → 시트 데이터를 매번 CSV로 내려받아 직접 넣기
API로 붙이면     → 시트가 원본, 대시보드는 항상 최신 시트를 읽음
```

# 2. gcloud CLI로 GCP 준비하기

## GCP(Google Cloud Platform)란?

**구글이 운영하는 클라우드 서비스의 본부**예요. 우리가 쓸 구글 시트·Gmail·캘린더 같은 API의 사용을 켜고 끄거나, 그 API를 호출할 '열쇠'(서비스 계정·키)를 발급받는 곳이 전부 여기입니다.

<aside>
💡 비유하면, **구글의 여러 기능을 회사 단위로 관리하는 '관리자 페이지'**예요. "이 앱이 구글 시트를 읽어도 된다"는 허가증을 여기서 발급받는다고 생각하면 됩니다.

</aside>

- **프로젝트(Project)**: GCP에서 작업을 담는 가장 큰 단위 (우리는 `spigen-497602` 사용)
- **API 사용 설정**: "이 프로젝트에서 구글 시트 API를 쓰겠다"고 켜는 스위치
- **서비스 계정 + 키**: 사람 대신 프로그램이 구글에 접속할 때 쓰는 로봇 계정과 그 비밀번호

콘솔(console.cloud.google.com) 웹 화면에서 클릭으로 다 할 수 있지만, 화면이 복잡하고 단계가 많아요. 그래서 터미널 명령어(gcloud)로 처리합니다.

## gcloud CLI란?

GCP도 GitHub처럼 **터미널에서 조작하는 공식 CLI**가 있어요. 바로 `gcloud`입니다.

<aside>
💡 2번에서 `gh CLI`로 GitHub를 터미널에서 다뤘죠. `gcloud`는 GCP 버전이에요. 콘솔(웹)에서 클릭으로 프로젝트 만들고 API 켜고 서비스 계정 만들 수도 있지만, 단계가 많고 헷갈립니다. **gcloud CLI를 쓰면 Claude Code가 이 과정을 대신 해줄 수 있어요.** (gh CLI와 똑같은 원리 — Claude Code가 조작 가능한 CLI)

</aside>

**Claude Code에 아래 프롬프트를 그대로 입력합니다.**

```markdown
gcloud CLI로 GCP를 준비해줘. (gcloud가 없으면 설치부터 안내해줘)

1. 현재 GCP 프로젝트를 spigen(spigen-497602)으로 설정
2. Google Sheets API 사용 설정
3. 서비스 계정 생성 (이름: spigen-sheets-reader)
4. 그 서비스 계정의 키(JSON)를 발급
5. 키에서 client_email, private_key를 꺼내 .env에 저장 (절대 커밋 금지)

각 단계에서 실제로 실행하는 gcloud 명령어도 같이 보여줘.
```

- **참고 — Claude Code가 실행하는 gcloud 명령어**

    ```bash
    gcloud config set project spigen-497602                    # 프로젝트 지정
    gcloud services enable sheets.googleapis.com               # Sheets API 켜기
    gcloud iam service-accounts create spigen-sheets-reader    # 서비스 계정 생성
    gcloud iam service-accounts keys create key.json \         # 키(JSON) 발급
      --iam-account=spigen-sheets-reader@spigen-497602.iam.gserviceaccount.com
    ```

<aside>
⚠️ **이 부분이 제일 헷갈리는 구간이에요. 천천히 같이 합니다.** 권한 오류가 나면 메시지를 그대로 Claude Code에 붙여넣어 해결하세요.

</aside>

# 3. 실습 — 구글 시트를 대시보드에 연결하기

먼저 읽어올 구글 시트를 준비하고, 2번에서 만든 서비스 계정 이메일에 '보기' 권한으로 공유합니다.

**Claude Code에 아래 프롬프트를 그대로 입력합니다.**

```markdown

시트를 수정하면 새로고침 시 반영되게 해줘.
```

<aside>
⚠️ 시트 ID·탭 이름은 본인 것으로 바꾸기. 키 값 자체를 프롬프트에 직접 붙이지 마세요(이미 .env에 있음).

</aside>

# 4. 앱에 AI 넣기 — Gemini API

<aside>
💡 **Claude Code = 만드는 도구 / Gemini API = 만든 앱 안에서 사용자에게 AI 기능을 제공.** 지금까지 AI는 '만들 때' 쓰는 도구였는데, 이번엔 만든 대시보드 '안'에 AI를 넣습니다.

</aside>

### 왜 Gemini API인가

- 오늘 GCP에서 키 발급하는 흐름과 한 곳에서 이어짐
- Google AI Studio에서 키 발급이 서비스 계정보다 훨씬 간단 (수업에 유리)
- 무료 티어 넓고, 한국어·독일어 강함, 표·이미지도 입력 가능(멀티모달)

### API 키 발급

1. aistudio.google.com 접속 → 구글 로그인
2. Get API key → Create API key
3. 키 복사 → .env에 GEMINI_API_KEY로 저장 (절대 커밋 금지)

<aside>
💡 서비스 계정 JSON과 달리 한 줄짜리 키라 훨씬 쉬운데, 똑같이 비밀번호 취급합니다.

</aside>

### 실습 — 대시보드에 'AI 인사이트' 버튼

```markdown
Context7 MCP로 Gemini API를 Next.js에서 호출하는 모범 사례를 확인해줘.

그 다음, 대시보드 상단에 'AI 인사이트' 버튼을 추가해줘.
버튼을 누르면 현재 화면의 핵심 지표(매출 추이, 베스트셀러, 재고 위험)를
Gemini API에 보내서 '이번 주 요약 + 액션 3가지'를 카드로 생성해줘.
키는 .env의 GEMINI_API_KEY를 쓰고, API 호출은 반드시 서버에서 처리해줘.
```

<aside>
⚠️ **키 호출은 반드시 서버 쪽에서.** 브라우저(클라이언트)에 키가 노출되면 안 됨 → '서버에서 처리해줘' 문구를 꼭 포함.

</aside>

### 확인하기

- [ ]  버튼 클릭 → 몇 초 뒤 AI 요약 카드가 뜰
- [ ]  데이터가 바뀌면 요약 내용도 바뀜
- [ ]  브라우저 개발자도구 Network에 키 값이 안 보임

# 5. API 제한사항 — 할당량 · rate limit

<aside>
💡 외부 API·AI API는 공짜·무제한이 아닙니다. 한도를 알아야 안전하게 설계할 수 있어요.

</aside>

### 꼭 아는 3가지

- Quota(할당량): 하루/분당 호출 가능 횟수 — Sheets는 분당 읽기 제한, Gemini는 무료 티어 분당·일일 한도
- Rate limit: 짧은 시간에 몰아치면 차단 — 시트 셀마다·행마다 Gemini 호출하면 즉시 초과
- 인증 만료·비용: 서비스 계정 키는 만료 없음 / Gemini는 무료 한도 넘으면 과금

### 한도를 피하는 설계

- 셀·행 하나씩 N번 부르지 말고 한 번에 묶어서(batch) 처리
- 결과를 캐싱해서 매 새로고침마다 호출하지 않기
- AI 요약은 '행마다'가 아니라 '버튼 누를 때 한 번' 또는 '하루 1회'

<aside>
⚠️ 429 (Too Many Requests)가 보이면 호출이 너무 잦은 것. 주기를 늘리거나 batch로 묶으세요.

</aside>
