# 로그인 기능 추가하기

# 1. 외부인 차단이 필요한 이유

- 지금 상태: 배포된 URL을 아는 사람이면 누구나 접속 가능
- 데이터베이스에 실제 업무 데이터가 들어있으니, 아무나 보면 안 됨
- 목표: 슈피겐 임직원만 들어올 수 있도록 로그인으로 막기

[](https://supabase.com/docs/guides/auth)

# 2. Supabase Auth란

<aside>
💡 **Supabase Auth = 회원가입/로그인을 Supabase가 알아서 처리해주는 기능.** 이메일/비밀번호, 매직 링크(이메일 링크), 구글·카카오 등 여러 방식이 있어요. 오늘은 **Google 계정 설정 없이 바로 되는 이메일/비밀번호 + 매직 링크**로 외부인을 막습니다. Google 로그인은 콘솔 설정이 더 필요해서 마지막 5번(선택)에서 따로 붙여봐요.

</aside>

1. supabase.com → spigen-dashboard 프로젝트 → Authentication → Providers
2. **Email** Provider 켜기 — 이메일/비밀번호 로그인과 매직 링크가 모두 이 하나로 처리됩니다
3. (데모 편의) Authentication → Settings에서 **Confirm email**을 잠시 꺼두면, 가입하자마자 바로 로그인돼서 수업 때 끊김이 없어요 (운영은 켜두는 게 안전)

<aside>
💡 **이메일/비밀번호 vs 매직 링크**

- 이메일/비밀번호: 가장 익숙한 방식. 비밀번호를 직접 만들고 입력
- 매직 링크: 비밀번호 없이, 입력한 이메일로 온 링크를 누르면 로그인. 외워야 할 비밀번호가 없음

</aside>

# 3. 실습 — 로그인 페이지 추가하기

**Claude Code에 아래 프롬프트를 그대로 입력합니다.**

```markdown
Supabase MCP와 Context7 MCP를 활용해서 이 프로젝트에 로그인 기능을 추가해줘.

1. /login 페이지에 두 가지 로그인 방식
   - 이메일 + 비밀번호 (회원가입 / 로그인)
   - 매직 링크 (이메일만 입력하면 로그인 링크 발송, signInWithOtp)
2. 대시보드 우측 상단에 로그아웃 버튼
3. 로그인 안 한 사용자는 대시보드를 볼 수 없고 자동으로 /login으로 리디렉션
4. Context7로 Supabase Auth 이메일 로그인 모범 사례(Next.js App Router, @supabase/ssr 기준)를 참고하면서 진행해줘

지금은 Google 로그인은 넣지 말고 이메일 방식만 구현해줘.
```

<aside>
💡 **응용:** "회사 이메일 도메인(@spigen.com)만 가입되게 해줘"처럼 외부인을 더 좁히고 싶을 때 추가로 요청. (정식 화이트리스트/RLS는 운영 단계 주제)

</aside>

# 4. 재배포 + 확인

코드가 바뀌었으니 다시 올려야 인터넷에 반영됩니다. 아래 프롬프트로 커밋·푸시하면 Vercel이 자동 재배포해요.

```markdown
방금 작업한 내용을 GitHub에 커밋하고 푸시해줘.
커밋 메시지: feat: 로그인 기능 추가
```

1~2분 뒤 Vercel URL을 시크릿 창에서 열어 확인합니다.

- [ ]  비로그인 상태에서 접속 → /login으로 자동 이동
- [ ]  이메일/비밀번호로 회원가입 → 로그인 → 대시보드가 보임
- [ ]  매직 링크로도 로그인됨 (메일함의 링크 클릭)
- [ ]  로그아웃 클릭 → 다시 /login으로 돌아감

# 5. 용어 정리

- Auth(인증): 지금 접속한 사람이 '누구인지' 확인하는 과정
- Provider: 로그인 수단 — 이메일, 구글, GitHub, 카카오 등
- 매직 링크(Magic Link): 비밀번호 대신 이메일로 받은 일회용 링크로 로그인하는 방식
- 시크릿 창(Incognito): 로그인 안 된 '외부인' 상태를 테스트할 때 필수
